# Dependency assessment

Reviewed: 2026-11-04. This is a candidate assessment, not a deployment or proof of live protection. Versions and releases can change; recheck them before a change. The [task backlog](../TASK.md) owns acceptance status.

## Priority: Cloudflare Tunnel

Cloudflare advises upgrading `cloudflared` to at least 2026.10.2 after the eMudhra intermediate-certificate compromise. The previously documented Mac and Linux observations predate that minimum. A version installed on disk does not prove which binary a running service has loaded. Determine that separately for every relevant connector. [Cloudflare's incident notice](https://blog.cloudflare.com/emudhra-certificate-compromise/) explains the issue and its recommended minimum.

As of this review, the [official release](https://github.com/cloudflare/cloudflared/releases/tag/2026.10.7) was 2026.10.7. Mac ARM64 archives for 2026.10.2 and 2026.10.7 were downloaded into disposable directories, checked against GitHub's published release-asset SHA-256 values, and executed only with `--version` and offline configuration commands. No connector, token, or live configuration was changed. Matching an archive hash to a digest obtained from the same distribution source is an integrity check, not independent signature verification.

The installed 2025.11.1 binary and both candidates accepted a synthetic, secret-free ingress configuration and selected the expected terminal, WebSocket, upload and fallback routes for five ordinary fixture URLs. This checks configuration parsing and route selection only: it does **not** check the live rules, Access policy, JWT validation, certificate validation, an authenticated tunnel, or reconnection. Cloudflare's [release notes](https://github.com/cloudflare/cloudflared/blob/master/RELEASE_NOTES) also record path-handling and update-timer changes between these versions; the synthetic result cannot prove compatibility with a different rule set.

Before a production change, independently identify the owner and version of each connector, capture its exact current configuration and binary provenance privately, and evaluate a patched candidate using an authorized isolated Access application. Test the three routes with approved and unapproved identities, a new and existing WebSocket, and reconnection to the same disposable job. Prepare and test a component-specific rollback with a patched, known-good binary and configuration. Reverting to a pre-2026.10.2 binary may reintroduce the certificate risk and must not be treated as a secure rollback. Cloudflare warns that an update requires a service restart and that stopping a connector drops its long-lived connections; see its [update guidance](https://developers.cloudflare.com/tunnel/guides/update-cloudflared/). No production rollback or restart has been verified here.

## Runtime and terminal components

| Component | Observed or pinned baseline | Candidate and compatibility considerations |
| --- | --- | --- |
| Node.js | The recorded Mac development environment used 23.10.0; the Linux fixture pins 22.23.4. | [Node.js lists v23 as end-of-life](https://nodejs.org/en/about/previous-releases). The official 24.22.2 ARM64 archive matched its published `SHASUMS256.txt`. In a separate checkout, its binary completed an immutable Yarn install with an initially empty cache and passed all 18 current Mac tests. Builds under 24.22.2 and 23.10.0 then produced matching inline HTML SHA-256 values using that same installation. This is not a live-service migration test. |
| ttyd | Mac candidate: 1.7.7. The imported Linux snapshot recorded 1.7.4. | [ttyd 1.7.7](https://github.com/tsl0922/ttyd/releases/tag/1.7.7) is the upstream release checked here. The [1.7.5 release](https://github.com/tsl0922/ttyd/releases/tag/1.7.5) changed the embedded client and client-option handling; 1.7.4 made terminals read-only unless writable mode is enabled. Compare the exact host build and preserve its origin and socket protections before an upgrade. |
| tmux | The Mac observation was 3.6a; the disposable Linux fixture pins 3.7c. | [tmux 3.8](https://github.com/tmux/tmux/issues/5584) changes mouse defaults and introduces other UI changes. The maintainer says a complete tmux restart is required to run a new server; that would affect existing jobs. Test scroll, copy mode, mouse, session grouping and rollback with a separate server first. |
| xterm.js | The Mac lockfile pins `@xterm/xterm` 5.4.0, canvas addon 0.6.0 and WebGL addon 0.17.0. | [xterm.js 6.0.0](https://github.com/xtermjs/xterm.js/releases/tag/6.0.0) changes viewport/scrollbar behavior and removes the canvas addon. This project imports that addon, so a version bump alone is not compatible. Test rendering fallback, scroll, resize, input and accessibility before changing the package set. |

The clean Node 24 install reported existing peer-dependency warnings, and both builds reported outdated Browserslist data. The Node 23 comparison reused the installation created under Node 24; it was not a second independent clean install. Versions observed on one device or in a container do not establish versions or behavior on another device. No dependency has been installed into a live service by this assessment.
